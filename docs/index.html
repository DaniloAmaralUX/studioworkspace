Project Studio

Um hub visual local dos meus projetos — pastas locais e repositórios do GitHub — para achar, organizar e entrar neles rápido, com a próxima ação sempre visível.

i

Se você está lendo isso, provavelmente esqueceu como isso funciona. Isso é normal. Leia as 3 primeiras seções (2 minutos), abra a aplicação, e vá.

Por que existe

Meus projetos ficam espalhados entre pastas locais, repositórios no GitHub, Claude Code, Codex e PowerShell. Retomar exige lembrar onde parei e reconstruir contexto — e cada atrito multiplica a chance de perder o fio.

O problema
Custo alto de "achar de novo" o projeto certo e a próxima coisa a fazer.
A solução
Um painel único onde cada projeto vira card com status, stack, atividade e uma próxima ação editável.
A promessa
Achar em < 5s. Entender o estado em < 10s. Abrir em ≤ 2 cliques.
O diferencial
Configurador de foundation estilo shadcn/create com preview real.

Regras de ouro (não violar)

  1. Local-only (desktop). Servido só em 127.0.0.1. Nunca em 0.0.0.0, nunca porta pública. Emenda: a variante Studio Cloud roda na Vercel — sempre atrás de proteção, nunca exposta por acidente.
  2. Nunca guardar tokens. Desktop: GitHub via gh CLI já autenticado. Cloud: PAT fine-grained read-only que vive só como env var na Vercel — nunca em código, log ou KV.
  3. Não mover arquivos. Associar pasta ≠ copiar. Remover do hub ≠ apagar. Confirmar antes de clonar ou abrir.
  4. Sem agente embutido. "Trabalhar" = abrir no Claude Code Desktop / Terminal / Explorer. O CLI claude/codex não está no PATH aqui.
  5. Fatias verticais. Uma coisa por vez, ponta a ponta. Não construir o que está em "Fora do escopo".
  6. npm, não pnpm. Bug conhecido de shadcn/pnpm neste Windows.

Como rodar

Dois processos, cada um numa porta local:

# tudo de uma vez
./start-workspace.ps1

# ou manualmente:
cd backend  && npm install && npm run dev   # 127.0.0.1:5178
cd frontend && npm install && npm run dev   # 127.0.0.1:5177

Abra http://127.0.0.1:5177 no navegador. O backend precisa estar de pé (senão o hub mostra a faixa "Workspace Service não está rodando").

!

Se gh não estiver logado, a aba GitHub não carrega. Rode gh auth status — o app não faz login por você.

Como usar

1. Adicionar um projeto

Clique em + Projeto na topbar. Duas abas:

  • Pasta local: cola o caminho ou escolhe. O backend valida, checa duplicata, detecta a stack. Não copia nada.
  • GitHub: lista seus repos via gh repo list. Selecionar cria um card só com metadados — não clona ainda.

2. Deixar a próxima ação visível

No card, clique no campo "Próxima ação" e escreva uma coisa concreta ("escrever landing e conectar API"). Salva sozinho no blur. É o que você vê primeiro quando volta.

3. Abrir e trabalhar

Botão Abrir no card mostra só os abridores detectados:

  • Explorer — abre a pasta.
  • Windows Terminal (wt -d) — já no diretório certo.
  • Claude Code Desktop — via protocolo claude://.
  • VS Code / Cursor — só aparecem se estiverem no PATH.

Se o projeto for GitHub ainda sem clone, ele confirma antes de gh repo clone num diretório de trabalho — daí abre.

4. Achar rápido

Ctrl+K foca a busca. Filtra por nome, tag, owner/repo, stack.

Filtros ao lado: por tag, por stack, por fonte (Local/GitHub). Ordenação padrão: última atividade.

5. Configurar foundation de um projeto (R5)

Entra no projeto local → aba Foundation. Painel de 3 colunas estilo shadcn/create:

  • Esquerda: decisões (framework, base color, tema, fonte, radius, densidade, ícones).
  • Meio: preview real com componentes shadcn reagindo aos tokens.
  • Direita: comando shadcn gerado + salvar (.workspace/foundation.json + .workspace/DESIGN.md).
→

Aplicar tem três modos: tudo, só tema, só fontes. O comando sempre aparece antes de rodar.

Studio Cloud (variante na Vercel)

O mesmo hub, no ar: studioworkspace-mauve.vercel.app. Mesmo repositório, mesmo frontend — o backend vira funções serverless em api/ e os dados vivem num Redis (Upstash).

O que funciona na nuvem
Hub de projetos (KV) · repos do GitHub (PAT read-only) · próxima ação com IA (AI Gateway) · galeria de temas · Foundation salva no hub
O que é só do desktop
Abrir no Claude/VS Code/Explorer · clone sob demanda · scaffold de projeto novo · carimbo (AGENTS/CLAUDE/MCP) · status git local
Meu Registry
Os 36 temas são um registry shadcn real em /r/*.json — em qualquer projeto: npx shadcn@latest add <url do tema>
Como deploya
push na main = deploy. Por isso commits ficam locais até decidir publicar. vercel.json na raiz é a única fonte de config.
!

Pendência de segurança: ativar Vercel Authentication → All Deployments no dashboard (a URL hoje está pública). Decidir antes se o registry /r/ deve continuar aberto.

O que isto NÃO é

Se você se pegar querendo adicionar algo daqui, pare e volte pro escopo.

  • Não é IDE, terminal, Figma, Claude Code nem Codex — é o que conduz entre eles.
  • Não tem agente embutido, streaming, nem agentes em paralelo.
  • Não é multiusuário, não tem billing, não tem marketplace. (A Studio Cloud existe, mas é o meu hub no ar — single-user, atrás de proteção.)
  • Não importa automaticamente todos os repos — você escolhe quais entram.
  • Não é um canvas estilo Figma nem um empacotamento desktop.

Quando eu travar

Regra pessoal: se eu passar mais de 5 minutos sem saber o que fazer, aplico este roteiro.

  1. Abro o hub. Vejo a próxima ação de cada projeto ativo.
  2. Escolho o projeto cuja próxima ação está mais concreta. Se nenhuma estiver concreta, o problema é essa — reescrever a próxima ação vira a próxima ação.
  3. Uma decisão por vez. Fatia vertical. Commit pequeno.
  4. Se travei numa fatia, pergunto: "isto já está no MVP ou virou enfeite?" — se enfeite, corto.
×

Nada destrutivo sem confirmação. Remover do hub é seguro (não apaga a pasta). Clonar é confirmado. Nunca há push/deploy/instalação automáticos.
